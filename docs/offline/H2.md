# H2 - review fixes: SMS corrections/consent, notifications gate, Split, banner

1. **Corrections starvation.** `CorrectionsSync._waitsForUpload` now holds only while the
   source/event row has fewer than 6 attempts. Network failures never count an attempt (C9), so
   attempts > 0 means the server itself refused it; its ever re-armed backoff no longer holds the
   correction. Held rows with attempts == 0 (network hold) still wait (Q-09).
2. **Consent at send time.** `CorrectionsSync(sharingGranted:)` is read just before each POST; when
   not granted, `redactedTemplate` is dropped and `corrected` is sent empty (the case itself still
   goes). The runtime passes `SmsSharedLearningConsentMirror.isGranted`. The mirror is refreshed
   by every server answer; the server is not asked again at send time (mirror only).
   **Integrator hand-off (WP-C11):** `privacy_permissions_screen.dart` must call
   `withdrawSharedLearningLocally(ref)` (features/sms_v2/providers/sharing_consent_provider.dart)
   FIRST, before the server withdrawal call.
3. **Notification gate.** `_inFlight` is claimed before the first await; SharedPreferences
   read-modify-write runs through one private Future-chain mutex; the daily slot is reserved
   atomically before showing and released if nothing was delivered.
4. **Stale preference refresh.** After the background fetch the pending queue and the cached
   copy's revision are re-checked; a refresh a toggle overtook is discarded.
5. **Split.** (a) `resetBackoff` now writes next_attempt=1 (a "made due early" marker); a 5xx/429
   attempt on such a row does not use up the attempt budget. (b) friend/group create refusal
   acknowledges the op(s) that actually hold the refusal (member op too). (c) `_stamp` is seeded from
   MAX(created_at) in the DB at first use per process.
6. **Banner.** Tapping the strip does nothing while a popup route (dialog/sheet, incl. the
   sign-out progress dialog) is on top. 6(b) is H1's (reachability).
