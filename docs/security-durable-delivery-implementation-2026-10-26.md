## Integration and activation contract

Examples and hosted Compose retain `SHARED_FEEDBACK_ADMISSION_ENABLED=false` and `NOTIFICATION_OUTBOX_ENABLED=false`. Disabled features allocate neither of their new pools. Existing customer OTP/Google sign-in, recovery consent and no-extra-password requirements remain unchanged. No encryption keys were generated, replaced or rotated.

For a later accepted deployment, apply the additive migrations to the reviewed target first. Provision a distinct private login for each enabled capability: `shared_feedback_runtime` inherits only `pandapay_feedback_admission`; `notification_worker_runtime` inherits only `notification_worker`. Do not reuse `app_user`, an owner or an administrative URL. Use the existing TLS validation and include one pool slot per enabled capability/serving process plus rollout overlap in the physical-cluster budget. The reviewed privilege policy now inventories those schemas, owners, capability memberships, exact routines and prohibited exposure access. Runtime readiness rejects elevated roles, other memberships, schema CREATE or direct private-table access.

`SHARED_FEEDBACK_DATABASE_URL` and `SHARED_FEEDBACK_HMAC_KEY` configure admission; keep the latter private and stable across replicas/restarts and register its version label for release. `NOTIFICATION_OUTBOX_DATABASE_URL` configures worker access. Normal notification-service URL/key variables configure the existing provider. The new flags require `shared_feedback_admission_acceptance` / `notification_outbox_acceptance` proofs tied to the exact source/configuration, including failure/recovery and operator acceptance. No credentials belong in this document or Git.

Delivery snapshots duplicate bounded customer-visible notification content in private PostgreSQL storage, with explicit retention; they do not encrypt that content or close I01. Owner/legal review must include this additional retained copy. Disabled schema additions create no historical delivery-intent backfill or remote sends. Worker claims are separate from financial effects and do not reissue a referral credit.

The queue uses PostgreSQL row locking for competing consumers; SKIP LOCKED does not eliminate table-level locks or prove load capacity. [PostgreSQL SELECT documentation](https://www.postgresql.org/docs/current/sql-select.htm). The provider's documented API idempotency support is organization-dependent and has a finite response-cache lifetime; a stable transaction ID alone is not equivalent protection. Do not promise exactly-once push delivery or billing without verifying the deployed service/version and account. [Novu idempotency documentation](https://docs.novu.co/api-reference/idempotency).
