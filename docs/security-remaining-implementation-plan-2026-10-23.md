## Execution rules

1. Capture hashes of pre-existing edits; delegate disjoint files. The coordinator integrates shared entrypoints and reviews every diff.
2. Establish a fresh baseline from the merged HEAD in a temporary checkout without `.env`, private keys or live URLs. Use synthetic providers and disposable databases only.
3. For each batch: preserve method/path/success payloads and supported clients; add negative, cross-user and failure regressions; run focused tests, then the affected whole suite. Record environment, counts and skipped checks. Pre-existing failures are not silently counted as passes.
4. Use additive, checksummed migrations. Never edit an applied migration or rename historical duplicate prefixes. Exercise fresh install, upgrade from the reviewed baseline, interrupted/repeated application and target runtime roles.
5. Stop promotion of a failing batch and repair it. Source rollback is allowed before schema/data transitions; afterward use the rehearsed forward repair/recovery procedure. An old binary unable to read new formats is not a rollback.
6. Update this ledger and both audit formats from actual evidence. Do not mark device/provider/managed-host acceptance complete from unit tests.
