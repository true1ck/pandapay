# WP-01 handoff: Contracts package

Branch `sms-v2/wp-01-contracts`. Types, validation and interfaces only; no behaviour.

## What was built

**Schemas and fixtures: `contracts/sms/v2/`**

- JSON Schemas (draft 2020-12): `common`, `fact`, `instrument`, `event`, `ledger_entry`, `rule_bundle`, plus `api/*.request.schema.json` for every route with a body and `api/*.response.schema.json` for `facts_batch`, `unknown_templates`, `corrections` and `sync` (the sync response carries `corrections`).
- The fact schema is `oneOf` with a `discriminator` on `factType`; each branch fixes that type's `attrs` and allowed or required amount roles.
- `error_codes.json` lists every code (210). `fixtures/valid/<kind>/` holds 53 files (at least 3 per fact type, 1 per other kind, plus request and response bodies). `fixtures/invalid/<kind>/<code>[~variant].json` holds 233 files, one or more per code; the file name is the single code the document must produce.
- Error codes are carried in the schemas as annotations: `x-code` (any failure at that node), `x-codes` (per failing keyword) and `x-required-codes` (per missing property). A failure with no annotation maps to `<kind>.malformed`. This is how the two languages agree.
- `embed_dart.js` regenerates `packages/pandapay_domain/lib/src/sms_v2/contract/schema_data.g.dart` from the schemas. A Dart test fails when the generated file is stale.
- Semantic invariants JSON Schema cannot express are coded identically on both sides: `fact.occurred_after_observed`, `fact.amount.duplicate_role`, `fact.evidence.span_invalid` (end before start), `event.anchor_mismatch`, `event.leg_duplicate`, `ledger.category_requires_external_to`, `ledger.category_source_mismatch`, `bundle.rule.same_as_invalid`, `bundle.rule.duplicate_id`.

**Dart: `packages/pandapay_domain/lib/src/sms_v2/contract/`, exported from `lib/sms_v2.dart`**

- `sealed class Fact` with 10 final subclasses; value types `Amount`, `InstrumentMention`, `Counterparty`, `Provenance`, `Span`; `Instrument`, `Event`, `LedgerEntry` (with sealed `LedgerEndpoint`: instrument, external, `ownUnresolved`), `RuleBundle`, `Rule`, `Emit`, `LinkRule`, `CategoryRule`, `IgnoreRule`, `SenderEntry`, `MerchantAlias`, `CounterpartyPurpose`.
- Enums carry wire names (`WireEnum`). Everything is immutable with value equality (derived from `toJson`), `fromJson` (validates first, throws `ContractException` with codes) and `toJson`. `validate()` returns the same codes as the server.
- `schema_validator.dart` is a small interpreter for the schema subset the schemas use. It runs the same schema files as Ajv.
- `interfaces.dart` holds the interfaces exactly as specified, plus the supporting types (`InstrumentResolution`, `LinkContext`, `LinkResult`, `CategoryInput`, `CategoryDecision`, `Totals`, `ReviewItem`, `ReviewKind`).

**Node: `api/src/sms_v2/contracts.js`**: Ajv 2020 (`strict`, `allErrors`, `discriminator`), compiled once. Exports `validateFact`, `validateInstrument`, `validateEvent`, `validateLedgerEntry`, `validateBundle`, `validateRequest(route, body)`, plus `validateResponse(route, body)`, `errorCodes` and `SCHEMA_DIR`. Each returns `{ok, errors: [{code, path}]}`.

**Phone: `app/lib/features/sms_v2/`**: `flag.dart` (`kSmsPipelineV2`, `smsPipelineV2EnabledProvider`), `storage/schema.dart` (`SmsV2Schema.ensure`, `installedVersion`, own `sms_v2_schema_version` table, never touches `PRAGMA user_version`, idempotent, runs in a savepoint).

**Touch points**: `api/package.json` (+ `ajv`, `ajv-formats`; lock file updated), `app/pubspec.yaml` (`assets/sms_rules/`), `.github/workflows/build-and-test.yml` ("Contracts" step), `app/assets/sms_rules/baseline_bundle.json` (empty, version 0, `signature: null`).

## Deviations and choices to confirm

1. **Dart validates documents, not requests.** The request and response fixtures are checked only by the Node suite. The Dart side covers fact, instrument, event, ledger entry and bundle (the Dart types list has no request types). The nested fact, instrument, event and ledger codes inside a request are the same codes, so a Dart request validator would be thin if WP-09 or WP-11 want one.
2. **Schema subset interpreter in Dart** instead of hand-mirrored checks. A `dart test` guard (`embedded schemas match ...`) keeps the embedded copy in step. After editing any schema, run `node contracts/sms/v2/embed_dart.js`.
3. **Enum values the contract did not list**, chosen to make the schemas strict:
   - `issuerKind`: `bank`, `card_network`, `wallet`, `broker`, `gateway`, `biller`, `other`.
   - Rule `status`: `draft`, `active`, `provisional`, `paused`, `retired`.
   - Link rule `singleLeg`: `complete`, `awaiting_leg`, `review`.
   - Link `join.reference`: `ignore`, `prefer`, `require`.
   - Category rule `match`: `token`, `exact`, `prefix`, `contains`.
   - Link leg `match` keys: `factType`, `direction`, `purpose`, `instrumentKind`, `phase`, `evidenceOnly` (the last two added so `LINK-IPO` and `LINK-RECEIPT` can be expressed).
   - Ignore rule `reason` reuses the info categories.
   - Sync `aiResults` item: `{templateHash, status: pending|ready|rejected, ruleId?, ruleVersion?}`; sync `corrections` item: `{caseId, sourceKey, status: open|decided, decision|null, reason|null}`.
4. **Time fields** are UTC `...Z` strings (pattern plus `date-time`); `dueAt`, `asOf` and `expiresAt` too. `dueDate` and `statementDate` are `YYYY-MM-DD`. `provenance.ruleVersion` and `bundleVersion` are required integers (0 for user facts).
5. **Mention fields**: all six `InstrumentMention` keys and all four `Counterparty` keys are always present (nullable), which keeps round-trips canonical. Optional (`?`) fields are omitted when null.
6. **Upload rules** in `facts_batch.request`: no `info` facts, `evidence` must be empty, `instrument.raw` must be null.
7. **Regex dialect lint** (no backreferences, no nested quantifiers) is left to `sms_rules_cli lint` (WP-02/WP-03 tooling). The contract only enforces flags (`i`, `m`, `s`) and the 2,000-character limit.

## Follow-ups for other packages

- **Docker image**: `api/Dockerfile` builds from `api/`, so `contracts/sms/v2` is not in the image. `contracts.js` reads it from `../../../contracts/sms/v2` or from `SMS_V2_CONTRACTS_DIR`. WP-08 (or deploy) must copy the directory into the image, or set the variable.
- **Server tests**: `npm test` globs `test/*.test.js`, so the contract test is not part of it; run `node --test test/sms_v2/contracts.test.js` (the CI Contracts step does). WP-08's `check_sms_v2.js` should syntax-check `api/src/sms_v2/*.js`.
- **Fixtures were generated** by a one-off script and are now source files. Edit the JSON by hand (or add fixtures) and keep one invalid fixture per error code; the test checks both directions.
- WP-02 may ask for `normalizeSenderBrand` to be exported next to the contract; it is not part of this package.
- The index status in `work-packages.md` was not touched (outside WP-01's paths); the orchestrator marks M0 "Contracts frozen".
