# WP-12 correction tracing and local effects

Status: In progress. The service foundations are implemented for orchestrator integration. The full WP-12 completion gate remains open.

Implemented in this branch:
- DecisionTrace stores identifiers, fact types, amount roles, instrument matching steps, link legs and category source locally. Stage attribution covers every correction kind.
- CorrectionsService applies category choices, template ignores, new user facts for amount/date/merchant/kind edits, fact reassignment and explicit link edits. User-confirmed events are reprojected with ledger and display rows in the same savepoint. The original anchor remains as an original leg when a user fact replaces its money leg.
- Preferences stay local. Reportable corrections queue with their local change. Shared review receives only compact trace and kind without consent. Consenting examples pass through WP-00 redaction and skeleton hashing.
- CorrectionsSync retries offline cases, retains work on account change, acknowledges by exact queued payload and applies owner-scoped decision status.
- Server correction intake validates the frozen request, referenced fact/event ownership, stage, consent and template hash. Idempotent case rows flag testers and attestation eligibility.
- Private admin grouping and decisions use learning.read/learning.publish, fresh MFA for decisions, feature flag, and audit writes. Data fixes return review drafts. Code fixes export only explicit reviewed synthetic examples.
- New migration and SQL test cover owner isolation and blocked customer decisions.
