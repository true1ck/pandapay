# WP-10 AI per template

Implemented server flow on `codex/sms-v2-wp10-templates`, based on `e28210f` with CCR-001 and WP-13 security available.

## Behavior

- `POST /sms/v2/unknown-templates` validates the frozen request, checks redaction again, requires current purpose-specific consent and calls the attestation and rate hooks. PostgreSQL repeats privacy checks and enforces the profile's 50-item daily cap in one transaction.
- Unverified monitor submissions are stored as held. Only verified, consented submissions count toward shared frequency and can authorize AI work. The first verified sample replaces an earlier held sample. A sender conflict for the same hash is rejected. Hashes come from the phone's original template identity because redaction changes printed values.
- One queue row exists per hash. Private workers claim popular templates first, then recent live templates, then older ones. A lease prevents concurrent calls. An interrupted provider call becomes failed after its lease expires, avoiding an unbounded retry bill.
- Calls reserve shared PostgreSQL RPM and TPM capacity. The default RPM is 60. TPM and model are required configuration. Output-token limit and optional per-million token prices are configurable. Cost records retain model, input/output/total tokens and latency, including repair calls. Missing pricing appears explicitly in metrics.
- The prompt includes redacted text, brand, frozen schema data and up to five public rule summaries. It excludes profile IDs, source SMS and example bodies from existing rules. Gemini's `generateContent` JSON mode is used with a bounded response and timeout. Tests use a mocked provider.
- Draft validation checks the Rule schema, metadata, exact template and sender scope, a hash-derived rule ID, regex dialect, named groups, populated sample captures, emitted attrs, examples and conflicting family words. Validation runs in a disposable worker thread with a timeout. Two distinct synthetic positive examples and two negatives are required. The worker permits one repair pass.
- Sync returns provisional rules only for templates the account submitted. Revisions are allocated under a transaction advisory lock so cursor advancement follows commit ordering. Later submissions of an already drafted template still receive it. CCR-001's optional `aiResults[].rule` is used.
- Consent revocation removes submitter access in the consent transaction. Profile deletion removes its association and orphan redacted templates. Cost records remain as platform accounting. Queued work loses its lease when no eligible submitter remains.
- Private admin routes list templates, show daily AI usage and copy ready provisional rules into ordinary WP-09 drafts. That explicit promotion removes the template-hash restriction. Reviewed publication still uses the golden gate.

## Worker operation

Run `node api/scripts/run_sms_v2_templates.js`, or add `--once` for a single iteration. Configure `ADMIN_API_DATABASE_URL`, `SMS_V2_JOB_ADMIN_ID`, `GEMINI_API_KEY`, `SMS_V2_AI_MODEL` and `SMS_V2_AI_TPM`. The active actor needs `learning.publish`. Optional settings are `SMS_V2_AI_RPM`, `SMS_V2_AI_MAX_OUTPUT_TOKENS`, `SMS_V2_AI_INPUT_USD_PER_MILLION` and `SMS_V2_AI_OUTPUT_USD_PER_MILLION`.

Provider request fields follow the [official Gemini generateContent API](https://aistudio.google.com/api-reference/generate-content). Deployment scheduling, credentials and a paid provider call remain release operations.
