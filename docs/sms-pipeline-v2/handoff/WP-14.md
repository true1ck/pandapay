# WP-14 phone pipeline wiring

Status: In progress on `codex/sms-v2-wp14`, based on integration merge `87d9c78`.

- The Shortcut's text parameter reaches the native spool as the supplied sender. The spool reads it back with the message, and the Dart batch retains tagged headers as received. Person conversion can still yield a handle or an absent sender, depending on the Shortcut input.
- Intake strips the five observed iOS filter annotations for the safety gate and contact-name classification. The capture record and source identity keep the raw sender. This capture correction also applies to legacy intake.
- `FactStore` uses the existing `v2_facts` table. It validates contract facts, scopes operations to the account, preserves the first fact and upload receipt on replay, and excludes info facts from upload selection.
- The next slice connects capture to interpretation, instrument resolution, linking, and ledger projection in one local transaction. Verified bundles and batched sync follow, along with consent handling, cross-device identity and device smoke tests. The new store is ready for that wiring.

The stored pipeline now interprets chunks of up to 500 messages, resolves and updates instruments, builds link context from stored facts and events, resolves categories, and atomically writes events, ledger and Activity rows. It records v2 source decisions and local review items. Retry and account-isolation tests pass, including a forced rollback. All 15 scenario totals match after processing one message at a time and after processing a batch.

The facts upload queue strips evidence and raw instrument tokens. Acknowledgements compare the exact sent payload so in-flight edits remain queued. Gzip uploads stay within the server's compressed and inflated limits, use the existing frozen request shape, and coalesce concurrent triggers. Failed requests retain the batch with bounded exponential backoff. The cache verifies downloaded and cached bundles through the required verifier and preserves the last compatible version.

Production lifecycle scheduling, cross-device merges, stats, correction delivery, key-conflict adoption, and device performance/smoke verification remain in progress. The shared intake path accepts an explicitly prepared v2 pipeline. The default app providers still need that composition before this package is complete.

The foreground runtime now composes the verified bundle cache, category snapshot, local pipeline, durable upload, and pull. Startup, resume, reconnect and a 15-minute foreground timer use it behind the build flag. The legacy AI timer has a flag guard. Both repository SMS import entry points accept the v2 handler, and background intake defers interpretation. Tests cover the direct repository routing, shared intake, foreground drain and two-device reconstruction with persisted cursor and rollback.
